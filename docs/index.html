System- & Projektdokumentation

Web3 Personal Fitness & Command Center Dashboard

Status: ● Aktiv & Deployed
Infrastruktur: Base L2 & Vercel
Version: 1.1.0 (Mai 2026)

1. Architektur & Systemübersicht

Das Projekt ist als hochperformante, serverlose Single Page Application (SPA) konzipiert, die als persönliche digitale Kommandozentrale dient. Sie aggregiert private Leistungskennzahlen und ermöglicht das zensurresistente Publizieren von Marktanalysen und persönlichen Statements. Das System verzichtet bewusst auf eine traditionelle Datenbankstruktur und setzt stattdessen auf ein hybrides Datenhaltungsmodell.

Die Architektur teilt sich in drei primäre Schichten auf: Das statisch kompilierte Web-Frontend, eine serverlose API-Integrationsschicht für geschützte Legacy-Daten (Garmin Connect Cloud) sowie das dezentrale State-Management direkt im Ethereum Layer-2 Netzwerk (Base Mainnet).

2. Frontend-Architektur & UI-Komponenten

Das User Interface basiert auf nativem HTML5, Vanilla JavaScript (ES6+) und Tailwind CSS. Die Benutzeroberfläche nutzt ein reaktives, tab-basiertes Navigationssystem, das über die JavaScript-Funktion switchTab(tabName) gesteuert wird. Nicht aktive Bereiche werden per CSS-Klasse hidden vollständig aus dem Render-Tree entfernt.

Zur Optimierung der Ästhetik auf mobilen Geräten wurde die Navigationsleiste mit einer horizontalen Scrollfunktion ausgestattet, wobei störende visuelle Bildlaufelemente über dedizierte Tailwind-Klassen plattformübergreifend unterdrückt wurden: 

<nav class="flex gap-1 bg-slate-950 p-1 rounded-lg border border-slate-800 overflow-x-auto [scrollbar-width:none] [-ms-overflow-style:none] [&::-webkit-scrollbar]:hidden max-w-full w-full sm:w-auto">

Clientseitige Pagination

Da der Umfang der Fitness-Rohdaten beträchtlich ist, implementiert das Frontend eine Client-seitige Pagination über die Routinen renderKraftTable() und renderCardioTable(). Die maximale Tabellenkapazität pro Segment ist über die Konstante const itemsPerPage = 10; fest definiert.

3. Garmin Live-Sync Integration

Die Erfassung physischer Datenströme erfolgt über eine automatisierte Integrationsschicht zur Garmin Cloud. Beim Laden des Dokuments (Event: DOMContentLoaded) wird asynchron die Funktion executeGarminLiveSync() instanziiert.

Das System sendet einen HTTP-Request an die serverlose Vercel-Umgebung unter dem Endpunkt /api/garmin_sync. Diese Serverless-Funktion verwaltet die OAuth-Tokens sicher serverseitig, fragt die Garmin-Connect-Schnittstelle ab und transformiert das empfangene JSON-Paket in die strukturierten Arrays für Kraft- und Cardiotraining.

4. Web3 & Base Blockchain-Infrastruktur

Das Herzstück des krypto-ökonomischen Sektors bildet die direkte Interaktion mit der EVM-kompatiblen Layer-2-Blockchain Base (Chain ID: 0x2105). Der Zugriff erfolgt ohne zentrale Vermittler auf der Leseebene über öffentliche RPC-Nodes.

Persistent State Management (Auto-Login)

Nach erfolgreicher Autorisierung über connectWallet() wird das Flag web3_logged_in = 'true' im localStorage gesetzt. Beim erneuten Laden verifiziert checkPersistedConnection() im Hintergrund über eth_accounts die Freigabe der Wallet, ohne dass ein lästiges Popup erscheint.

Clientseitiger Admin-Gatekeeper

if (userWalletAddress !== ADMIN_WALLET) {
    alert("Zugriff verweigert: Admin-Rechte erforderlich.");
    return;
}

Solidity Smart Contract

Der Kontrakt DashboardFeed.sol speichert Datenstrukturen permanent ab. Schreibrechte sind über den onlyOwner-Modifier exklusiv an die Admin-Wallet gekoppelt. Die Funktion getStatements() stellt die Daten als public view kostenfrei für das Frontend bereit.

5. Deployment- & Wartungsleitfaden

Wichtig bei Codeanpassungen: Nach jeder Aktualisierung der Frontend-Logik oder der Smart-Contract-ABI muss die Produktionsumgebung auf Vercel zwingend neu kompiliert werden.

Frontend-Deployment über das Vercel CLI

Die Synchronisation des lokalen Quellcodes mit der Serverless-Hostingplattform wird über das Terminal mittels expliziter Cache-Inaktivierung ausgeführt: 

vercel --prod --force

Dieser Befehl erzwingt den vollständigen Neuaufbau aller Edge-Routen, bereinigt den CDN-Cache an den weltweiten Edge-Standorten und stellt sicher, dass die geänderten RPC-Aufrufe sofort global verfügbar sind.
